# 开发培训任务

按编号完成任务。各项截止时间以培训系统为准。Q05、Q10、Q15、Q20 安排现场验收。

| 编号 | 工作内容 | 完成后应能做什么 | 验收方式 |
|---|---|---|---|
| [Q01](20项任务/Q01.md) | 工单台需求梳理 | 能把一句模糊的业务需求拆成角色、操作和预期结果，提出会影响实现的问题，并用现有接口核实哪些是事实、哪些还待确认。 | 提交审核 |
| [Q02](20项任务/Q02.md) | 版本管理与提交审查 | 能从上一版代码建立任务分支、提交并发起 PR，独立核对改动、完整 SHA 和检查结果，让别人能追溯一次交付。 | 提交审核 |
| [Q03](20项任务/Q03.md) | 共用控件与响应式布局 | 能把「手机上不好用」转成明确的布局与交互条件，用 AI 做一段小原型，再通过不同宽度、键盘和长文本实测，收敛到一套共用控件。 | 提交审核 |
| [Q04](20项任务/Q04.md) | 工单列表、新建和详情 | 能将列表、搜索、新建和详情串成可用流程，用稳定的工单 ID 定位记录，并把加载、空结果、失败、提交和校验分别呈现在页面上。 | 提交审核 |
| [Q05](20项任务/Q05.md) | 阶段验收一 · 工单界面 | 能按反馈复现界面问题、定范围修复并对照同一场景复测，还能现场修改一处核心逻辑，用日语说明是什么问题以及改了什么。 | 现场验收 |
| [Q06](20项任务/Q06.md) | 工单接口与权限测试 | 能把「谁可以看或改什么」写成接口契约和允许、拒绝两类测试，并解释错误返回顺序及数据之间的关系。 | 提交审核 |
| [Q07](20项任务/Q07.md) | 工单数据迁移至 SQLite | 能把文件数据迁入 SQLite，给业务数据设置主外键、约束和索引，使用参数化查询，并验证重启、重复迁移和失败恢复。 | 提交审核 |
| [Q08](20项任务/Q08.md) | 并发更新与创建幂等 | 能区分重复提交、并发写入和过期版本，用幂等键、版本条件与事务控制结果，验证同一次请求只落一条记录和对应事件。 | 提交审核 |
| [Q09](20项任务/Q09.md) | 工单页面接口联调 | 能将页面接入真实 API，防止慢响应覆盖新条件。遇到网络错误或版本冲突时，能保留用户输入并给出正确的重试路径。 | 提交审核 |
| [Q10](20项任务/Q10.md) | 阶段验收二 · 接口与数据 | 能用同一版本从浏览器追到 API 和数据库，验证角色权限、幂等、持久化和错误恢复，并用日语解释一次联调故障怎么处理。 | 现场验收 |
| [Q11](20项任务/Q11.md) | 故障定位与回归测试 | 能从可复现现象收集证据，判断 AI 提出的不同原因，用最小实验定位故障，再用修复前会失败、修复后会通过的测试固定结果。 | 提交审核 |
| [Q12](20项任务/Q12.md) | 批量更新工单状态 | 能实现带权限和版本检查的批量操作，在一条失败时让整批不写入，并让用户在跨页选择和冲突中仍能继续操作。 | 提交审核 |
| [Q13](20项任务/Q13.md) | 工单游标分页 | 能实现排序稳定的游标分页，处理连续翻页时的重复与缺项。能用查询计划和浏览器数据找出数据库、网络或页面渲染的开销。 | 提交审核 |
| [Q14](20项任务/Q14.md) | 编辑表单的草稿与冲突处理 | 能区分草稿和已保存数据，在保存失败、离开或版本冲突时保留工作，并用键盘和窄屏操作验证表单。 | 提交审核 |
| [Q15](20项任务/Q15.md) | 阶段验收三 · 代码审查 | 能审查 AI 生成或改写的代码，识别权限扩大、错误被吞、SQL 不安全和改动超出需求等问题，并用回归测试判断是否可以接收。 | 现场验收 |
| [Q16](20项任务/Q16.md) | 优先级筛选与统计 | 能把一条需求变更拆成保留项、改动项和回归项，明确筛选与统计的口径，并验证角色、URL 和旧流程都按约定工作。 | 提交审核 |
| [Q17](20项任务/Q17.md) | 分支合并与回归验证 | 能从共同版本拆分并行改动、处理文本冲突，也能用测试找出 Git 合并成功后仍然存在的行为冲突。 | 提交审核 |
| [Q18](20项任务/Q18.md) | 性能测量与故障验证 | 能设计可重复的性能测量，用原始样本和 p95 等数据判断是否真的变快，并在网络、数据库或版本冲突时核对业务结果。 | 提交审核 |
| [Q19](20项任务/Q19.md) | 候选版本检查与恢复演练 | 能固定一份可发布的版本，让构建、测试和本地预览对应同一 SHA，并分别演练代码回退与数据恢复。 | 提交审核 |
| [Q20](20项任务/Q20.md) | 结业项目 · 设备借还系统 | 能从一段业务原话独立接下一套系统，主动澄清需求，用 GitHub 跟进交付，用 AI 做原型并亲手验收，最后让其他人从干净环境跑通、验证并接手。 | 现场验收 |
