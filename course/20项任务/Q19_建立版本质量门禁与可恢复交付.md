# Q19 给候选版本补齐检查和恢复步骤

第 45–46 天，留 2 天。预计用时 4 小时。

固定一个 SHA，在本地跑基线、学员测试、核心函数、类型、构建和浏览器检查。用公开练习仓库练习 Actions，训练代码留在本地。写下迁移重试和恢复步骤，再走一遍。

先在 `exercises/Q19.ts` 独立完成 `releaseReadiness`。看[Q19 核心函数](../核心编码契约.md#q19-releasereadiness)，补三个自己设计的反例，先做一次核心提交，再请工具协助后面的工程改动。

从 [本题引导](../引导/08_性能与交付.md) 开始。接口以 [接口与数据](../契约/接口与数据.md) 为准。分支用 `feat/q19-release-readiness`。

## 改动范围

- `.github/workflows/`
- `README.md`
- `tests/learner/`
- `learning/Q19/`

## 具体要求

- 固定候选 SHA，按清单执行本地检查；公开的 Actions 练习使用示例仓库。
- 从空工作目录启动本地预览，走一次工单主路径。
- 梳理迁移可重入、数据兼容、代码撤销和数据恢复，演练一次。

## 交什么

交候选 SHA、检查结果、预览烟测和恢复记录。有未验证的环境或操作就列出来。

在 `learning/Q19/` 留 [交付记录](../模板/交付模板.md)，把实际失败和没有做过的检查写清楚。

- 检查对应同一 SHA。
- 本地预览经过 API 验证。
- 能分别说明代码和数据的恢复步骤。
