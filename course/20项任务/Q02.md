# 开发培训任务 Q02

## 版本管理与提交审查

从上一项的最终提交新建分支，修改启动说明，审阅暂存区差异后提交。将分支推送到个人 Fork，向培训仓库提交 Q02 的 PR。用本地训练工程运行基线测试、类型检查和构建。

- 用 GitHub PR 的 Commits、Files changed 和 Checks 页面分别核对提交、差异和检查结果。

改动范围包括 `README.md`、`.github/workflows/`、`learning/Q02/`。任务分支为 `feat/q02-github-delivery`。

在 `exercises/Q02.ts` 独立完成 [`parseBranch`](../核心编码契约.md#q02-parsebranch) 并补充三个自拟反例。单独提交后再继续工程改动。

## 提交材料

提交分支、检查记录及 PR 与本次提交的对应关系。

在培训仓库提交 PR，并将 PR 链接、完整提交 SHA、完成说明及 PR 截图上传培训系统。将检查记录整理到 `learning/Q02/`，格式见 [交付记录](../模板/交付模板.md)。

## 验收要求

PR 的源分支、完整 SHA 和检查结果应能相互核对。对照 Q01，说明本次 PR 新增的改动。如检查曾失败，注明修复前后的结果。

```sh
npm run check:task -- Q02
npm test
npm run test:learner
npm run typecheck
npm run build
```



### 审核提问

PR 在检查通过后增加了一次提交，此时应查看哪一次提交的检查结果？

コミット、プッシュ、マージの違いを説明してください。
