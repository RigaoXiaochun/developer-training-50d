# 开发培训任务 Q01

## 工单台需求梳理

开始前请按 [提交指南](../引导/02_GitHub交付.md) 创建个人 Fork 并克隆到本地。

先读 [Q01 的业务原话](../固定材料/业务原话练习.md#q01--一句话里有哪些待确认事项)，写下自己的理解和五个问题，再用固定资料逐项核对。

运行起始工程并确认 Vue 入口可打开。当前页面只有入口。按 [Q01 技术说明](../引导/01_需求与上下文.md) 检查本地 API，再从基线测试追踪一次新建请求，说明它如何进入服务端并写入存储。按角色整理页面、可用操作和异常情形，提出五个待确认问题，并依据需求说明逐项核对。

- 需求记录注明范围、可修改文件、接口约束、页面验收条件和验证方法。
- 结合固定需求材料，区分已确认、待确认和排除的需求。

工程改动限于 Vue 入口导航 `frontend/vue/App.vue` 和启动文档 `README.md`。需求记录放在 `learning/Q01/`，并参照固定需求材料。任务分支为 `feat/q01-requirements-baseline`。独立编码和自编测试按 [通用要求](../规范/训练方式.md) 提交。

在 `exercises/Q01.ts` 独立完成 [`normalizeDraft`](../核心编码契约.md#q01-normalizedraft) 并补充三个自拟反例。单独提交后再继续工程改动。

## 完成后应能做什么

能把一句模糊的业务需求拆成角色、操作和预期结果，提出会影响实现的问题，并用现有接口核实哪些是事实、哪些还待确认。

## 提交材料

提交角色与操作对照表、五个问题的确认结果及启动验证记录。

在培训仓库提交 PR，并将 PR 链接、完整提交 SHA、完成说明及 PR 截图上传培训系统。将检查记录整理到 `learning/Q01/`，格式见 [交付记录](../模板/交付模板.md)。

## 验收要求

需求记录应覆盖用户、工作人员和管理者，并列出页面尺寸和异常处理要求。说明示例身份和 JSON 存储的局限。提交变更后应能按启动文档运行工程。

```sh
npm run check:task -- Q01
npm test
npm run test:learner
npm run typecheck
npm run build
```



### 审核提问

以基线测试中的新建工单请求为例，说明接口如何识别角色、校验字段和写入数据。

### 日语说明

この要件について、確認済みの点と未確定の点を説明してください。

参考 [本项技术说明](../引导/01_需求与上下文.md) 和 [接口与数据规范](../契约/接口与数据.md)。
