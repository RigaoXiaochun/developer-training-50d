# 开发培训任务 Q17

## 分支合并与回归验证

从同一提交建立 A、B 分支，分别完成校验和布局改动。在临时整合分支合并，解决一处文本冲突，再复现并修复一处 Git 未标记的行为冲突。

- 演练分支名以固定材料为准。审核时说明三方合并、revert 和 reset 分别对历史和工作区产生什么影响。

改动范围包括 `frontend/vue/`、`tests/learner/`、`learning/Q17/`。任务分支为 `feat/q17-integration-review`。

在 `exercises/Q17.ts` 独立完成 [`threeWayMerge`](../核心编码契约.md#q17-threewaymerge) 并补充三个自拟反例。单独提交后再继续工程改动。

## 提交材料

提交两个分支和整合版本的 SHA、冲突处理记录和回归结果。

向培训仓库提交 PR。在培训系统填写 PR 链接、完整提交 SHA 和完成说明，上传 PR 截图。检查记录放在 `learning/Q17/`，格式见 [交付记录](../模板/交付模板.md)。

## 验收要求

整合后验证两项原始需求。记录共同基线、合并顺序及各提交 SHA，保证可以复现。说明撤销代码时如何保留已有业务数据。

```sh
npm run check:task -- Q17
npm test
npm run test:learner
npm run typecheck
npm run build
npm run test:acceptance -- Q17
npm run check:ui -- Q17
```

### 审核提问

选一处行为冲突，说明 Git 合并成功后它为什么仍会发生。

### 日语说明

マージ競合の解決方法と、マージ後の確認内容を説明してください。

参考 [本项技术说明](../引导/02_GitHub交付.md) 和 [接口与数据规范](../契约/接口与数据.md)。
