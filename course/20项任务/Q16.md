# 开发培训任务 Q16

## 优先级筛选与统计

根据需求变更单实现 `low`、`normal`、`high` 优先级筛选及 `/v2/overview`。统计基于当前身份可见且匹配搜索与状态的工单，在优先级筛选和分页之前计算。

先用 [Q16 的业务原话](../固定材料/业务原话练习.md#q16--需求变更) 整理你的理解，再对照变更单确认统计口径及要回归的行为。

- 本次范围为只读筛选及统计，排除优先级编辑、推送提醒和新增角色。
- 优先级筛选与数量使用 [页面测试标识](../契约/接口与数据.md#错误与前端定位)。

改动范围包括 `server/`、`frontend/vue/`、`tests/learner/`、`learning/Q16/`。任务分支为 `feat/q16-managed-change`。

在 `exercises/Q16.ts` 独立完成 [`parsePriority`](../核心编码契约.md#q16-parsepriority) 并补充三个自拟反例。单独提交后再继续工程改动。

## 完成后应能做什么

能把一条需求变更拆成保留项、改动项和回归项，明确筛选与统计的口径，并验证角色、URL 和旧流程都按约定工作。

## 提交材料

提交变更前后的约定、筛选操作记录和相关回归结果。

在培训仓库提交 PR，并将 PR 链接、完整提交 SHA、完成说明及 PR 截图上传培训系统。将检查记录整理到 `learning/Q16/`，格式见 [交付记录](../模板/交付模板.md)。

## 验收要求

筛选条件写入 URL。非法 URL 值恢复为“全部”，直接传给 API 的非法值返回 400。验证刷新与后退，复查游标、批量选择、创建、详情、冲突处理和手机布局。保持 v1 兼容。

```sh
npm run check:task -- Q16
npm test
npm run test:learner
npm run typecheck
npm run build
npm run test:acceptance -- Q16
npm run check:ui -- Q16
```
