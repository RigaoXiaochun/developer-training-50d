# 人负责判断，Agent负责受约束实现

审查前先看任务目标、非目标和文件清单。优先看数据库、权限、并发、依赖和共享组件，再读状态／失败／UI，最后核对测试。检查绿色对应哪个SHA，是否真实运行，是否只测了实现本身。

固定坏补丁卡提供六种审查机会；不需要编造Agent曾犯错。本人应给出可触发反例、影响、最小修复和回归。要求“解释这一块为什么改”，不是接受“已优化、企业级、无影响”等自评。

重构先有行为基线，API／函数外部语义不变，小步拆分、每次验证。文件少或行数短不等于低耦合，压缩语句也不算模块化。依赖升级、主题更换、顺手改权限都需独立理由和批准。

换会话时保留决策和事实，而非堆全量聊天。交接当前SHA、相关文件、真实失败、已确认方案、下一步和禁止项；先复核再继续。Agent给的根因必须通过实验验证。

独立编码区不能让Agent生成或修改。AI可用于讲解通用概念，但一旦针对独立题生成了实现，本次算练习，再关闭生成完成变体才作为独立证据。
