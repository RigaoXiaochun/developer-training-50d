# 从布局规则到可用界面

先画信息层级：页头与导航→标题和主要动作→筛选→结果→分页／连续加载→详情／表单。宽屏和手机使用同一份业务状态，手机可换呈现而不复制两套数据逻辑。先读规范、tokens和reference，再让Agent写组件。

统一box-sizing:border-box；普通内容保持文档流。Flex容器的可收缩文字常需要min-width:0，操作区保持可触达；长标题省略时必须另有全文入口。不要给body随便加overflow:hidden掩盖溢出。固定高度不能用于遮盖普通内容问题。

推荐状态归属：页面维护筛选、选中和当前详情；computed派生可见结果；列表与表单用props和事件，不直接改父对象。TS联合描述状态，不能到处用any和多个互相矛盾的布尔量。组件按职责拆，建议每个新增业务文件≤220行，不压成一行躲检查。

引导练习：先只做一条长标题卡片和一个字段的错误态，观察320／390／768／1440；把字号、圆角、焦点与禁用统一成共享规则，再实现其他页面。每次调整公共组件回归其全部使用处，不只截一张首页。

测试包含键盘Tab、Escape、焦点返回、200%缩放和底部安全区。主要触摸目标44px为课程标准，输入至少16px；实机软键盘没有条件测试就写未验证。UI评分≥85且无阻断才通过，不能靠主观“现代化”评分。

参考：[Vue组件](https://cn.vuejs.org/guide/components/registration.html)、[设计基础](https://developer.mozilla.org/en-US/curriculum/core/design-for-developers/)。
