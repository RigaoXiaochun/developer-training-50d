# 从业务原话到执行约束

先读代码再提方案。用`rg --files server frontend`找到入口，读server/app.mjs的路由、domain.mjs的权限与状态，再读tests/api.contract.test.mjs。运行npm test和dev，观察一条真实请求。先画一张数据流图：界面事件→api模块→路由→服务→仓储→响应，不需要先引入新框架。

把原话拆成“角色对对象做什么”，每条补前置状态、成功结果、禁止情况、异常和证据。例如“工作人员处理工单”还缺：谁的工单、哪些状态、谁能分配、重复或旧版本怎么办。对照固定FAQ后分别标已确认、非目标、真正待确认，不能用合理猜测代替事实。

执行顺序：①列现有行为和限制；②形成权限／状态矩阵；③写验收与非目标；④给Agent相关文件和契约；⑤只审计划；⑥允许一个小补丁；⑦读diff和验证。前6题有步骤，后面学员自己完成拆解。

任务包示例结构：目标／事实与未知／不做／允许文件／输入输出／异常／UI／验证。不要只有“企业级、完美、高性能”。也不要一次要求Agent完成所有未来题目。

先练习：从当前代码找出一条“页面能做但API不能做”的设想，引用真实路由解释。再将一条抽象要求改成可复现步骤。不能靠Agent复述一遍当理解。
