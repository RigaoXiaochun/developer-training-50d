# 接口与数据规范 v2.0

本文规定 HTTP 接口及存储行为。`core-specs.json` 规定独立函数的输入和输出。服务层负责将辅助函数返回的布尔结果或字段错误转换成 HTTP 响应。

## 连接与身份

前端相对路径`/api/training`，Vite4780代理到127.0.0.1:4781。API的createServer(filename)需保留：返回`listen(port)`（可用0随机端口）、`close()`；close关闭HTTP和底层数据库以便测试清理。测试不依赖存储内部对象。

公开`X-Training-Actor`仅模拟5个身份：user-01／user-02、staff-01／staff-02、manager-01。角色来自固定actors，不接受客户端任意role。此头不提供真实认证，不能移植生产。允许来源仅前端回环4780；本训练服务不开放公网。

GET `/health`不需要身份，返回`{data:{status:'ok',mode:'local-training-only'}}`；Q07后增加`storage:'sqlite'`。性能工具必须核对mode与storage，不能对基线JSON或业务服务器发负载。

## 字段与模型

|Ticket字段|类型／规则|
|---|---|
|id|string，TCK-十进制数字，服务端生成|
|title|string，trim后1—60 Unicode码点|
|description|string，trim后1—1000码点|
|category|support／billing／other|
|status|open／in_progress／resolved|
|priority|low／normal／high，新建normal；本期只读|
|ownerId／ownerName|string，创建人|
|assigneeId|string或null，只能staff或未分配|
|assigneeName|string，未分配时为未分配|
|createdAt／updatedAt|统一ISO UTC字符串|
|version|正整数，每次有效写入递增|
|archived|boolean，软归档后所有角色不可读|

Actor=`{id,name,role}`。Event=`{id,ticketId,actorId,action,at,version}`，action为CREATED／UPDATED／ARCHIVED。归档记录和事件保留数据库，归档后详情和事件HTTP均404。应用按文本渲染输入，不插入innerHTML。

## v1：必须保持兼容

GET `/v1/meta`→`{data:{actors,titleMax:60,descriptionMax:1000,pageSizes:[5,10,20]}}`。

GET `/v1/tickets?q=&status=all&page=1&pageSize=5`→`{data:Ticket[],meta:{page,pageSize,total,totalPages}}`。q trim后最长120 UTF-16单元，不区分大小写，匹配id或title；status缺省／空为all，否则只允许3种状态。page为1—100000整数，pageSize仅5／10／20。未知query400 UNKNOWN_QUERY，非法状态400 INVALID_STATUS，其余非法query400 INVALID_QUERY。

先权限和未归档→q／status→createdAt倒序、同时间id字典倒序→分页。totalPages最少1，超末页返回空数组和原请求page，不偷偷改页码。前端筛选变化自己回第一页。

GET `/v1/tickets/:id`→`{data:Ticket}`；GET `/:id/events`→`{data:Event[]}`。不可见与不存在统一404 TICKET_NOT_FOUND。

POST `/v1/tickets`仅user，JSON仅`{title,description,category}`，201→`{data:Ticket}`。unknown字段400；新记录open、normal、未分配、version1。前端失败保留输入。

PATCH `/v1/tickets/:id`含当前version和至少1个业务字段，200→最新Ticket：

|角色|可见范围（均未归档）|可改字段|状态规则|
|---|---|---|---|
|user|本人ownerId|title、description、category|仅open允许编辑|
|staff|assigneeId为本人|status|open→in_progress／resolved；in_progress→resolved|
|manager|全部|status、assigneeId|三状态均可设置；分配给staff或null|

未知字段400 UNKNOWN_FIELD，不允许字段403 ACTION_FORBIDDEN；version非正整数400 INVALID_VERSION，版本不同409 VERSION_CONFLICT，业务状态不允许409 INVALID_STATE，空变更400 EMPTY_CHANGE。允许的同值manager修改仍递增版本。并发旧版本必须拒绝，不覆盖。

DELETE `/v1/tickets/:id`仅manager，JSON`{version}`，200→`{data:{id,archived:true,version}}`；权限403、非法版本400、旧版本409。没有恢复归档接口。

## Q07：关系存储契约

表与最低列名：

- actors：id TEXT PRIMARY KEY，name，role。
- tickets：id TEXT PRIMARY KEY，title，description，category，status，priority，owner_id，assignee_id可空，created_at，updated_at，version INTEGER，archived INTEGER（0／1）。
- events：id（稳定唯一），ticket_id，actor_id，action，at，version。
- schema_migrations：version INTEGER PRIMARY KEY，applied_at。

约束：角色、状态、分类、优先级CHECK；version>0；归档0／1；owner／assignee／event引用外键；必要的NOT NULL。显示与存储的snake_case由仓储映射为camelCase。

索引至少论证`(owner_id,archived,created_at DESC,id DESC)`、`(assignee_id,archived,created_at DESC,id DESC)`和管理者`(archived,created_at DESC,id DESC)`，按查询计划说明，不盲目给每列加索引。搜索包含匹配可能扫描，诚实说明限制。

迁移按版本执行并记录成功，失败ROLLBACK、不清库。先导入基线JSON到新`.local/training.sqlite`，原JSON保留；25行、角色引用、事件及version核对。已有成功版本不重复导入。测试filename可能以.db结尾，不能依赖.json扩展名选择行为。

使用Node24.14的`node:sqlite`可避免额外数据库安装；该版本接口仍为开发中的同步API，不能以它推断生产多实例并发能力。[Node24.14官方SQLite说明](https://nodejs.org/download/release/v24.14.0/docs/api/sqlite.html)。允许按同一契约使用其他实现，但训练包验收基线是本地SQLite，不购买云数据库。

## Q08：创建幂等

POST可选`Idempotency-Key`，8—128字符、仅ASCII字母数字和`._:-`；缺省仍支持旧客户端，出现但非法400 INVALID_IDEMPOTENCY_KEY。

作用域`actorId+key`。将通过校验与trim的title／description／category按固定顺序规范化，再比较请求摘要；未知字段仍先拒绝。首次创建、事件、幂等结果在同事务提交。相同key和规范请求返回原201及原响应；同key不同规范请求409 IDEMPOTENCY_CONFLICT。即使原记录后来被改动，重放仍返回当初创建响应，不重新创建。

新增idempotency_keys表，至少actor_id、key、request_hash、response_json、created_at，`UNIQUE(actor_id,key)`。重启仍有效；本期不自动过期，不把内存Map当持久化。没有key的客户端不具备自动重试保障。

## Q12：原子批量状态

POST `/v2/bulk-status`仅manager，JSON仅`{items:[{id,version}],status}`。items为1—100项，version正整数，id不重复，status三状态之一。

200→`{data:{updatedIds:string[]}}`，顺序同请求。每条version+1、UPDATED事件同事务。全成或全不成，不能部分提交。

错误：非manager403 ACTION_FORBIDDEN；空／类型非法400 INVALID_BULK，>100为400 BULK_LIMIT，重复400 DUPLICATE_ID，非法version400 INVALID_VERSION，非法状态400 INVALID_STATUS；任何不存在／不可见404 BULK_NOT_FOUND；任何旧版本409 BULK_VERSION_CONFLICT。先检查可见范围，再报版本，不返回不可见ID的详情。

前端跨页选择保留，角色或任一筛选改变清空。100项时其余未选控件禁用并显示上限提示，已有选择仍可取消。默认不持续显示红色上限文字。提交失败保留选择，不能显示全成功。

## Q13：游标读取

GET `/v2/tickets?q=&status=all&pageSize=20&cursor=...`，pageSize整数1—100，默认20。q／status同v1。cursor缺省从头，否则base64url编码UTF-8 JSON`{createdAt,id}`，必须仅这两键、合法统一ISO UTC及TCK-数字id，非法400 INVALID_CURSOR。未知query400。

返回`{data:Ticket[],meta:{pageSize,nextCursor:string|null,hasMore:boolean}}`。权限与过滤后，按时间／id倒序，用WHERE位置和LIMIT(pageSize+1)查询；有更多时nextCursor为本页末项位置，否则null。前端条件改变重置游标，旧响应丢弃。游标不是授权凭证。

只保证当前数据下按位置继续，不承诺跨多次请求的事务快照；新插入顶部记录需刷新获取，已归档项后续不展示。不能下载全量再slice，DOM也须有界。

## Q16：优先级与统计

扩展`/v2/tickets`支持priority=all／low／normal／high，默认all，保持游标读取。新增／完成`GET /v2/overview`，支持v1的q／status／page／pageSize，加priority；返回data和meta，其中meta增加`priorityCounts:{low,normal,high}`。

计数集合＝当前身份可见、未归档、匹配q／status，在priority与分页前计算。total则在priority后。overview用于统计和有界分页兼容，不能替换掉游标列表。非法API priority400 INVALID_PRIORITY；v1带priority仍400 UNKNOWN_QUERY。

URL只要求保存priority，刷新与前进后退同步。未知URL值容错回all；清除回all。不得把前端容错规则变成后端静默接受非法输入。新增筛选先重置游标／页码／选择，不保留旧身份数据。

## 错误与前端定位

失败统一`{error:{code,message,fields?:{字段:string}},requestId}`，成功对象如上。400参数、401教学身份未知、403操作／来源禁止、404对象不可见或接口不存在、409版本／状态、413请求体>16KiB、415写请求非application/json、500内部失败。Q16前overview可返回501 EXERCISE_NOT_IMPLEMENTED。一次有多个问题时按服务处理次序返回首项，不要求聚合全部错误。

Vue测试标识data-testid：actor-select为固定身份select，ticket-search为自动生效input，ticket-status-filter为状态select；new-ticket打开表单；ticket-title-input、ticket-description-input、ticket-category-input为三个字段，ticket-submit提交；ticket-row带data-ticket-id=真实id；ticket-list、ticket-open、ticket-detail、detail-close；priority-filter、priority-counts。批量bulk-select／bulk-submit与错误表单按组件保持唯一明确作用域。

自动测试只覆盖固定子集；数据库约束、查询计划、失败注入、键盘、长文案、实机和源码审查仍需自己的证据。
