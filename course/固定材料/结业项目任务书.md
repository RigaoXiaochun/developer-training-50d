# Q20 结业项目任务书 · 设备借还系统

本项目使用 Vue 3、TypeScript、Node.js 24.14 或更新的 24.x 和 SQLite。截止时间以培训系统为准。

## 业务原话

> 办公室有些设备是大家共用的。有人借走了，群里问半天才知道在谁手里。领设备的人想用手机看现在能不能借，管设备的人需要知道谁还没还、哪些已经超期。做一个系统，把这件事管起来。

## 开始开发前

在 GitHub Issue 或项目需求记录中写下你对这段需求的理解。说明谁会用、他们各自要完成什么、成功时应该看到什么。列出会改变实现的待确认问题，并写明提问原因。

把关键问题交给带教确认。根据回复补齐本轮范围、权限、业务状态和验收情形。把范围拆成可验证的小任务，在 GitHub 上跟进进度。记录基础约定及之后发生的变更。

## 开发与验证

按照指定的技术栈，在 `capstone/` 完成一个可独立启动的 Web 系统。应有可操作的界面、服务端和持久化数据。实现登录与服务端权限校验。测试账号与样例数据支持复现完整流程，界面供桌面和手机使用。实际业务规则以确认后的需求记录为准。

可以用自然语言让开发工具先产出一段可操作的原型。选择一个最容易理解错的流程，从需求记录中取出角色、触发动作和期望结果交给工具。亲手走一次，对照结果给出具体反馈，再审查差异并验证。写清哪些决定由你作出、哪些实现由工具协助，以及你怎样证明它按预期工作。

按已确认的验收情形实现完整流程。覆盖正常办理、权限拒绝和业务冲突，核实刷新及重启后的数据。验收人员应能在干净环境按说明启动系统，使用样例账号复现流程。样例只使用虚构数据。

在 `capstone/` 提供 `package.json`、`package-lock.json` 与 `README.md`。审核使用 `npm ci`、`npm run typecheck`、`npm test`、`npm run build`。README 写明数据库初始化、服务启动、测试账号与端到端验收步骤。

## 交付与现场验收

- 提交需求确认记录、GitHub Issue 或项目记录、PR、最终提交 SHA、启动和验证说明。
- 提供数据库初始化或迁移步骤、样例账号生成方式、关键操作和异常的验证记录。
- 在现场以指定版本演示。解释一处需求取舍和一处工具协助的改动，展示你怎样核对结果。
- 根据审核人给出的边界变化，现场独立修改并验证一处关键逻辑。用日语简要说明所做功能、异常处理和验证结果。
